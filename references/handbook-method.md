# 竞品分析可执行方法

本文件从《竞品分析完全入门手册》提炼而来，用于指导 Codex 执行竞品分析。完整转写见 `source-handbook-full.md`。

## 核心定义

竞品分析的本质是：用外部参照帮助自己做更好的产品、运营、商业或战略判断。

竞品分析不是：

- 竞品截图合集。
- 功能清单堆砌。
- 为了证明自己原本想法正确的材料。
- 看到竞品上线一个功能，我方就必须跟进。

好的竞品分析要完成三层工作：

1. 事实：竞品做了什么，证据是什么。
2. 解释：竞品为什么这么做，服务什么目标。
3. 行动：我方应该跟进、差异化、延后还是放弃。

## 分析任务卡

正式分析前先写任务卡：

- 本次目标：为了支持什么决策。
- 核心决策：立项、功能、体验、定价、增长、采购、汇报等。
- 分析对象：直接竞品、间接竞品、替代方案、潜在竞品。
- 重点维度：市场、用户、定位、功能、体验、商业、增长、技术、数据等。
- 交付形式：Markdown、HTML、PPT 大纲、表格等。
- 时间范围：例如最近 6 个月产品更新、价格、内容和用户反馈。
- 数据口径：下载量、流量、价格、转化、互动率等口径要统一。
- 受众对象：老板、产品团队、运营团队、客户或公开读者。

## 竞品类型

- 直接竞品：用户、需求、核心功能、商业模式高度相似。
- 间接竞品：目标用户或需求部分重叠，但产品形态不同。
- 替代方案：用完全不同方式满足同一底层需求。
- 潜在竞品：目前不是竞品，但资源、能力或用户基础可延伸进来。

选择竞品时不要只看“长得像”，而要看它是否影响用户选择。

## 信息来源

优先交叉验证：

- 官方资料：官网、帮助中心、价格页、公告、白皮书、API 文档。
- 产品实测：注册试用、核心流程体验、截图、录屏、客服咨询。
- 用户声音：应用商店、小红书、知乎、微博、B 站、社群、客服反馈。
- 市场数据：行业报告、财报、招股书、第三方数据平台。
- 流量与渠道：Similarweb、Google Trends、百度指数、SEO 工具、内容平台。
- 组织与技术：招聘 JD、技术博客、专利、开源仓库、工商和投融资新闻。

数据可信度原则：

- 一手实测和官方公开文件通常更可靠。
- 第三方估算适合看趋势和相对比较。
- 社媒内容适合发现用户语言和情绪，但不能直接代表总体用户。
- 关键结论至少用两类证据支撑。

## 六步流程

1. 明确目标：服务哪个决策，避免无边界资料收集。
2. 选择竞品：按直接、间接、替代、潜在分类，精选深度分析对象。
3. 确定维度：根据目标选择市场、用户、功能、体验、商业、增长等。
4. 收集数据：用公开资料、实测、用户反馈和第三方数据交叉验证。
5. 分析判断：定量看规模和趋势，定性解释原因和用户选择动机。
6. 输出报告：结论前置，给出建议、优先级、证据、风险和下一步。

## 常用维度

### 市场分析

回答这个赛道有没有机会、竞争是否激烈：

- 市场规模和增长趋势。
- 用户需求强度和频次。
- 市场集中度和头部壁垒。
- 进入门槛：资金、技术、内容、供应链、牌照、品牌。
- 政策、平台规则、技术变化。
- 用户付费意愿和客单价。
- 供给侧稳定性。
- 未来 6-12 个月可能改变格局的变量。

### 用户分析

不要只问竞品做了什么，要问用户为什么选择它：

- 用户是谁：年龄、城市、职业、经验、预算、组织角色。
- 场景是什么：什么时候用、在哪里用、任务是否紧急、失败成本多高。
- 动机是什么：省时间、省钱、确定性、身份认同、降低风险、提升效率。
- 替代行为：不用这个产品时，用户怎么解决同一问题。

### 定位分析

观察点：

- 官网首屏标题。
- 核心卖点。
- 目标用户。
- 场景锚点。
- 证据体系：案例、数据、资质、客户 Logo、达人背书。
- 品牌语气：专业、年轻、高端、效率工具感等。

定位句模板：

```text
面向【目标用户】，在【核心场景】中，我们提供【关键能力】，帮助用户获得【明确结果】，相比竞品的差异是【差异化优势】。
```

### 功能分析

不要只填支持/不支持，要看：

- 功能覆盖：核心场景是否覆盖。
- 功能深度：高级配置、自动化、协作、权限、导出。
- 任务效率：步骤数、耗时、跳转、阻塞点、成功率。
- 结果质量：准确、稳定、可控、可复用。
- 差异化：独有能力、用户强感知、复制成本。

### 体验分析

围绕关键任务路径记录：

- 任务：用户想完成什么。
- 入口：从哪里开始。
- 步骤：每一步点击、输入、等待。
- 成本：耗时、认知负担、失败次数。
- 结果：是否成功，输出质量如何。
- 感受：顺畅、困惑、焦虑、惊喜。

体验结论要量化，避免只写“好看”“流畅”。

### 商业分析

拆解：

- 收入来源：订阅、买断、广告、佣金、增值服务、企业定制、硬件销售。
- 价格体系：免费版、基础版、专业版、团队版、企业版、试用期、折扣。
- 权益设计：容量、次数、功能、协作、权限、导出、服务、SLA。
- 转化链路：什么时候弹付费，怎么展示价值，是否有案例和保障。
- 成本结构：研发、内容、算力、履约、销售、客服、渠道。

价格不能孤立比较，要和目标用户、价值感知和成本结构一起看。

### 增长分析

按漏斗拆：

- 认知：品牌词、达人种草、媒体报道、SEO、广告。
- 访问：官网、落地页、应用商店、活动页。
- 注册：登录方式、授权范围、注册门槛。
- 激活：新手引导、模板、示例数据、首个成功任务。
- 留存：提醒、任务、积分、内容更新、社群、订阅通知。
- 转化：付费墙、限免、优惠券、套餐对比、客服销售。
- 推荐：邀请奖励、分享海报、作品传播、口碑裂变。

## 评分模型

评分只辅助判断，不是结论本身。

建议 1-5 分：

- 5：原生支持且能力深，能形成完整任务闭环。
- 4：原生支持且成熟，但部分环节依赖组合或配置。
- 3：可用，但体验、深度或闭环弱于头部。
- 2：间接支持，主要依赖评论、表格、第三方或手工流程。
- 1：基本不覆盖该场景。

权重来自本次目标，不固定等权。

## 报告结构

推荐结构：

1. 摘要结论：3-5 条最重要发现和建议。
2. 背景与目标：为什么做，要支持什么决策。
3. 竞品选择：名单、类型、选择理由。
4. 市场概况：规模、趋势、格局、风险。
5. 对比分析：按重点维度展开。
6. 关键洞察：竞品强弱、用户选择理由、未满足需求。
7. 机会判断：可切入定位、场景、功能、渠道。
8. 行动建议：做什么、不做什么、优先级、风险和下一步。
9. 附录：数据来源、截图、访谈、原始表格。

结论写法：

```text
我们发现【事实/数据】，说明【背后的原因或趋势】，因此建议【行动】，预期影响【收益】，需要注意【风险/前提】。
```

## 检查清单

交付前检查：

- 目标是否清楚，能否服务具体决策。
- 竞品选择是否有理由，而不是凭感觉。
- 是否区分直接、间接、替代、潜在竞品。
- 分析维度是否围绕目标，而不是模板堆砌。
- 关键数据是否注明来源、时间和口径。
- 是否实际体验过核心流程或说明无法实测。
- 是否整理用户真实反馈和高频痛点。
- 是否比较定位、功能、体验、商业和增长。
- 是否解释竞品为什么这样做。
- 是否说明我方应该跟进、差异化还是放弃。
- 是否给出优先级和下一步行动。
- 是否有风险、假设和待验证问题。
